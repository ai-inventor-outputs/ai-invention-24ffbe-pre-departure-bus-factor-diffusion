## Research Findings

Full recipe verified against primary sources; see research_report.md for complete detail. Summary of the load-bearing corrections and confirmations:

(1) DOA FORMULA — CONFIRMED with one CORRECTION to the plan's working hypothesis: DOA(md,fp) = 3.293 + 1.098*FA + 0.164*DL - 0.321*ln(1+AC), where FA=1 iff md created f (else 0), DL = the RAW COUNT of md's own commits touching f (NOT a recency/days term as the plan's initial scan guessed), and AC = count of commits touching f by any developer OTHER than md [1]. The weights are reused verbatim from Fritz et al.'s prior Degree-of-Knowledge work [3], not refit by Avelino et al. [1]. Authorship threshold: normalized DOA > k=0.75 of the file's max, AND absolute DOA >= m=3.293 [1]. DOA is computed only at YEARLY full-history snapshots starting from repo creation, never on an arbitrary sub-year window [2] — a pre-departure 6-12 month DOA metric is therefore a genuine unvalidated extension, not a reproduction of Avelino et al.'s method, and its file-first-authorship (FA) definition needs explicit resolution at the window boundary.

(2) TRUCK FACTOR ALGORITHM — CONFIRMED: greedy loop that checks file coverage by remaining authors BEFORE each removal; stops the instant coverage would drop below 50%; tf = number of authors actually removed while coverage stayed >=50% [1]. No stated minimum project-size floor; no stated tie-breaking rule for equal-coverage authors (flagged gap).

(3) TFDD / ABANDONER / ACTIVE-INACTIVE — CONFIRMED, with ONE PLAN ASSUMPTION REFUTED: abandoner = last commit >=1 year before the repo's own most recent commit; the 1-year threshold's harmonic mean of precision(0.82) and improvement(0.55) is 0.66, beating 6mo(0.44), 1.5yr(0.64), and 2yr(0.62) [2] (all figures now fully recovered per Table II, not just the winning cell). Active/Inactive is a strictly BINARY state machine (all TF-devs abandoned = Inactive/TFDD; a new TF-developer arriving = Active again), and survival is defined relative to the LAST observed TFDD only [2] -- the hypothesis's reference to a graded thriving/maintained/dormant/dead framing has NO basis in either primary source and must be built as an independent extension if desired. There is no explicit fixed post-TFDD survival window (e.g. no '18 months' anywhere in the paper) -- survival is measured against yearly TF recomputation up through the dataset collection date [2]. Headline numbers re-confirmed exactly: 1,932 projects, 315 (16%) with a TFDD, 128/315 (41%) survived, median 32 vs 47 developers at TFDD for surviving vs non-surviving (p=2.2e-4), Cliff's d=0.64/0.79 for post-TFDD commit volume/share [2].
